# Evals Directory - Quality Assurance & Testing Hub

This `evals/` folder acts as the Quality Assurance & Testing Hub for the AI application. Its primary purpose is to measure, test, and score how well the AI is performing (i.e., whether it writes correct SQL, whether it hallucinates, and whether it follows instructions). 

Broadly, it handles two types of evaluations: 
1. **Offline Testing**: Testing the AI against static datasets before deploying.
2. **Online Tracing**: Grading real production traces from Arize Phoenix.

---

## 1. Data Generation & Extraction (Offline Workflow)

These scripts handle the generation of test datasets and their conversion into human-readable formats.

* **`create_golden_dataset.py`**: A script that runs the AI against hundreds of test questions, records its SQL and text responses, and outputs a "golden" JSONL dataset containing all the inputs, outputs, and latency metrics. 
* **`extract_to_csv.py`**: Takes the JSONL output from the script above and converts it into a `human_eval.csv` spreadsheet so your human QA team can easily read it, grade it, and add notes.
* **`dataset.py`**: A simple utility script that loads these `.jsonl` files into Python lists so the other scripts can read them.
* **`datasets/` (Folder)**: This is where all the actual JSONL and CSV files live (e.g., `human_eval.csv`, `generated_golden_dataset.jsonl`, etc).

---

## 2. Automated AI Judges ("LLM-as-a-Judge")

Instead of humans reviewing everything manually, these scripts use a strict LLM to automatically grade responses:

* **`judge.py`**: Contains the core logic for the AI judges (like `QAJudge` and `GroundednessJudge`). If you run this script directly with `--run-qa`, it will loop through an offline dataset and automatically fill out the pass/fail labels and failure categories into the QA schema.
* **`run_trace_groundedness_eval.py`**: Connects to the live **Arize Phoenix** server, downloads actual real-world conversations (spans), runs them through the `GroundednessJudge`, and pushes the pass/fail grades back to the Phoenix UI as annotations. *(Note: When using this, pass the base64-encoded GraphQL ID for the project, e.g., `--project UHJvamVjdDo2`)*.

---

## 3. Regression Testing (CI/CD Tests)

These scripts are built to enforce constraints and fail builds if performance degrades.

* **`test_groundedness.py`** & **`test_sql_correctness.py`**: Pytest files designed to be run in a CI/CD pipeline (e.g., GitHub Actions) to automatically fail a build if the AI stops writing correct SQL or starts hallucinating too much after a code change.
* **`sql_schema_adherence.py`**: Evaluates whether the SQL generated by the AI strictly follows the database schema rules (e.g., ensuring it doesn't try to query columns that don't exist).
